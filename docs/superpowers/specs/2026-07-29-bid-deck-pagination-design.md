# 通用正文转高质量 HTML 展示页与逐页质量门禁设计

## 1. 目标

上游直接提交类似 `test.md` 的连续 Markdown 正文。MCP 服务负责完成正文规范化、事实提取、语义分页、逐页内容规划、模板选择、资产规划、HTML 生成、逐页 QA、定向修复和交付，不要求调用方或 Codex Agent 手工编写每页 `SlideSpec`。

本轮验收输入为 `test.md`，目标页码为 59、60、61、62，正式交付为四个自包含 A4 横向 HTML 页面。PNG、质量报告和 manifest 只作为 QA 证据，不要求生成 PPTX。

## 2. 设计原则

1. 分页先于排版：先建立完整的四页语义边界，再分别生成页面，避免排版阶段随意删减事实。
2. 页面独立验收：每页拥有独立 run、质量报告和修复次数；任何一页不合格时，不得用其他页面的平均分掩盖。
3. 事实可追溯：所有数字、时限、审批条件和项目名称均关联回源文档事实，页面压缩只能改写表达，不能修改口径。
4. 模板驱动而非模板特例：模板被解析为槽位、容量、视觉层级、设计 token 和文档类型适配度；生产代码不按某个 slug、页码、章节名或验收文案分支。
5. Agent 只补资产：本轮 Codex 仅调用内置 `imagegen` 完成 MCP 规划的图片；分页、文案、模板、HTML 和 QA 全部由 MCP workflow 负责。
6. 可恢复与幂等：相同 `requestId` 和输入指纹复用已有规划与页面 run，从失败页继续，不重复生成已完成页面或资产。

## 3. 通用页面蓝图与本轮验收叙事

以下 59–62 页叙事只是 `test.md` 的验收期望，不得作为生产规则。生产规则先从每页源文本提取语义角色（结论、事实、指标、流程、对比、证据、图片需求），再生成不依赖模板的 `PageBlueprint`，最后与模板槽位能力匹配。

- 固定对接、动态调配、有序变更三类响应机制总览。

### 第 60 页：岗位职责与履职保障

- 进度跟踪、工作日报和定期汇报。

## 4. MCP 接口

### `plan_deck`

输入：

- `sourceMarkdown`、`sourceText` 或 `sections`，三者必须且只能提供一个。
- `pageNumbers`：本轮为 `[59, 60, 61, 62]`。
- `documentType`：`bid | proposal | presentation`，本轮为 `bid`。
- 可选 `templateSlug`、`requestId` 和内部文本模型配置。

输出：

- `deckPlanId` 和源文档指纹。
- 有序 `slides`，每页包含页码、标题、源段落范围、事实引用、内容块、设计意图和模板选择。
- 全局 `assets`，资产 ID 必须包含页码，例如 `p59-img-001`。
- 每张图片的用途、尺寸、替代文字和独立提示词。

### `generate_deck`

输入：

- `deckPlanId` 或完整的已校验 `plannedDeck`。
- `externalAssets`，使用稳定资产 ID 接收 Agent `imagegen` 生成的 data URL。
- 可选 `requestId`。

行为：

1. 验证规划指纹、页码和资产完整性。
2. 为每页创建独立 slide run，复用现有 `generate_slide`、run store 和质量循环。
3. 逐页生成和修复；已交付页面在重放时直接复用。
4. 所有页面通过后执行跨页一致性检查。

输出：

- deck 状态：`needs_assets | running | partial | delivered | failed`。
- 每页 runId、状态、HTML 路径、PNG 路径、质量分和剩余问题。
- deck manifest 与跨页一致性报告。

### `get_deck`

按 `deckPlanId` 或 deck runId 返回整体状态、逐页状态和允许读取的交付物，不接受任意文件路径。

### 模板知识工具

- `inspect_template`：解析已有 HTML 模板，返回语义槽位、容量、栅格、视觉占比、色板、字体、组件和适用的页面意图。
- `create_template_from_reference`：接收优秀展示页/PPT 截图或 HTML 参考。有多模态 provider 时直接产生结构化 `TemplateBlueprint`；无 provider 时返回稳定的分析任务和 schema，允许外部 Agent 只回注蓝图。服务端负责确定性编译、清洗、渲染 QA 和入库。
- `list_template_knowledge`：返回已入库模板的来源、版本、能力标签、质量证据和适配历史，使 workflow 可复用而非重复临摹。

参考图只用于学习布局、层级、节奏和风格 token，不将参考图整张当背景交付，不复制其可识别文案、品牌标识或受保护资产。

## 5. 语义分页算法

1. 使用现有 content normalizer 将 Markdown、纯文本或 sections 归一为有序章节和段落。
2. 使用 fact extractor 提取数字、项目、时限、角色、条件和审批关系。
3. 根据标题边界、段落主题和事实依赖形成不可随意拆开的内容单元。
4. 调用方给出页码数量时，以该数量为硬约束；未给出时根据模板容量估算页数并受配置上限限制。
5. 使用容量成本模型分配内容单元：标题、正文字符、列表项、表格行、数字密度和图片槽分别计入预算。
6. 保持原文顺序，并使每页具备一个清晰主题。不得拆开同一审批步骤，不得把限定条件与结论分到不同页面。
7. 可选内部文本模型仅用于改进摘要和主题命名；模型不可改变页数、事实值、源顺序和模板白名单。无文本 API 时确定性规划仍必须完成。
8. 规划完成后锁定页间边界。逐页修复只压缩当前页表达，不擅自把内容移到相邻页；容量无法满足时返回明确分页错误，要求重新规划整个 deck。

## 6. 通用模板能力模型与选择策略

- 每个模板都通过 `TemplateProfile` 声明语义槽位、槽位容量、支持的内容角色、位图面积上限、信息密度区间、表格/流程/指标能力、必需结构地标、主题与文档类型适配度。
- 页面规划器输出与模板无关的 `PageBlueprint`；选择器根据容量、角色覆盖率、密度、图片需求和文档策略评分，不根据 slug 特判。
- `documentType=bid` 等策略通过能力标签表达，例如上限视觉占比、最小字号、必需页码/标题/证据区，而非维护一组模板名白名单。
- 模板映射器将内容角色分配到槽位，记录每次裁剪、压缩、合并或降级决策；不允许静默丢失源事实。
- 求解不成功时返回可诊断的不匹配原因，并可在同主题或调用方允许的主题内重选模板。
- 本轮验收应选中现有标书风格模板，但这是能力匹配结果，不是生产代码中的固定偏好。

## 7. 图片边界

- `plan_deck` 为每页最多规划一张支持性图片；没有必要时可只使用模板 SVG 图标和结构组件。
- 图片提示词必须从该页事实生成，明确标书用途、构图槽位、写实或示意属性以及无文字、无标识、无水印约束。
- 本轮使用 Codex 内置 `imagegen`，不用图片 API，也不使用 CLI fallback。
- 生成结果复制到项目工作区后，以 data URL 注入 `generate_deck.externalAssets`。
- 不复用同一张图片跨页；所有图片标注“AI 生成，非项目实景”。
- MCP 不得感知 Codex 私有路径；manifest 只记录资产 ID、内容哈希、MIME 类型和项目内缓存路径。

## 8. 逐页 QA 与修复

每页都必须独立通过以下硬门禁：

- 仅一张 A4 横向页面，无滚动溢出或裁切。
- 无远程资源、脚本、未解析占位符、密钥或失败图片。
- 正文最小字号不低于模板规定的 8.5pt。
- 标题、正文和图示没有意外重叠或异常换行。
- 章、节、页题、总结和页码结构完整。
- 页码与规划一致。
- 所有高风险事实引用存在且值与源文档一致。
- 图片面积符合标书模式上限。

软评分继续使用事实保真、结构、可读性、布局、资产和技术六个维度。每页目标分数不低于 90，交付门槛保留为可配置值且本轮设置为 90。

修复顺序：

1. 对溢出的具体内容块做事实保持型压缩。
2. 修复字号、间距、图片裁切或组件映射。
3. 在标书白名单内最多切换一次模板。
4. 每页最多三次尝试；仍未通过则该页失败，deck 状态不得标记为 delivered。

跨页检查只验证一致性，不替代逐页 QA：模板主题、章节命名、字体、色板、页码连续性和事实口径必须一致。

## 9. 持久化和失败语义

- deck manifest 保存源指纹、页面规划、资产映射、每页 runId、当前阶段和跨页报告。
- `needs_assets` 表示规划已完成但外部图片尚未回注。
- `partial` 表示至少一页已交付，但仍有页面在运行或失败。
- 单页重试不得重跑其他已交付页面。
- 相同 requestId 但输入指纹不同必须拒绝，避免覆盖旧交付物。
- artifact 查询限制在 `page-<number>.html`、预览、质量报告和 manifest 的封闭名称集合。

## 10. 测试策略

- 单元测试：标题感知分页、页数硬约束、原文顺序、事实依赖、容量预算、通用页面蓝图、能力型模板选择、槽位匹配和图片面积规则。
- 泛化测试：使用两组不同标题、页码和行业的虚构文档，并对模板 slug 重命名，确认分页、规划、选择和 QA 结果不依赖 `test.md` 或现有模板名。
- 模板学习测试：对 HTML 参考直接提取蓝图；对图像参考验证 `needs_analysis`/provider 两条路径；只有通过清洗、渲染和能力验证的模板才能入库。
- 契约测试：`plan_deck`、`generate_deck`、`get_deck` 的结构化输出、错误脱敏和资产 ID 稳定性。
- E2E：不配置文本和图片 provider，以结构化 Markdown 和外部 data URL 资产生成四页。
- 恢复测试：中断第 61 页后继续，确认第 59、60 页不重复生成。
- 渲染测试：逐页运行 Chromium 门禁并保存质量报告。
- 模板回归：现有六个模板继续通过基础解析和渲染测试。
- 真实验收：以 `test.md` 生成第 59–62 页，使用 MCP 规划的提示词分别调用内置 `imagegen`，回注后重新生成并进行全尺寸人工检查。

## 11. 验收标准

1. 一次 `plan_deck` 调用从连续正文得到四页有序计划，无需 Codex 手工拆写每页内容。
2. 一次 `generate_deck` 调用在资产齐备后生成 `page-59.html` 至 `page-62.html`。
3. 四页分别达到不低于 90 分，所有硬门禁通过，且没有剩余错误。
4. 页面通过通用能力匹配选中现有标书模板体系，信息密度来自正文事实、职责、时限、面积和证据，而非大图或装饰。
5. 关键事实包括 1 名固定人员、8 个项目、30 分钟、1 小时、不少于 5 个工作日、3 个工作日和 1–2 名后备人员，均与 `test.md` 一致。
6. 正式交付目录只需要四个自包含 HTML；QA 目录可附带 PNG、quality 和 deck manifest。
7. 对模板 slug 重命名或替换为能力等价模板后，四页规划与事实覆盖不变；生产代码中不存在 59–62、`test.md` 文案或当前 slug 的业务分支。
8. 模板知识工具能将 HTML 参考或结构化图像分析蓝图编译为可验证的自包含 HTML 模板，保存来源、能力和 QA 证据以便复用。
